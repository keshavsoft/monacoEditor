Building a Monaco-Like Code Editor

Understanding how an editor identifies, tokenizes, parses and provides language features.

1. Objective

The objective is to understand how Monaco Editor recognizes and processes different programming languages and to use the same concepts to build a simple Monaco-like code editor.

Main Question: How does a code editor understand JavaScript, Python, HTML, CSS and other languages?

A code editor does not necessarily execute the code. It analyzes source text using language-specific rules and services.

2. High-Level Architecture

Code Editor ↓ File / Language Detection ↓ Language ID ↓ Language Definition ↓ Tokenizer ↓ Syntax Highlighting ↓ Parser / AST ↓ Semantic Analysis ↓ Language Services ├── Autocomplete ├── Diagnostics ├── Hover ├── Definition └── References

These are separate responsibilities that work together to create an intelligent code editor.

3. Language Detection

First, the editor needs to determine which language the uploaded file contains. A simple application can use the file extension.

FileExtensionLanguage ID
app.js.jsjavascript
main.ts.tstypescript
index.html.htmlhtml
style.css.csscss
main.py.pypython
README.md.mdmarkdown
function getLanguage(fileName) {

    const extension = fileName
        .split(".")
        .pop()
        .toLowerCase();

    switch (extension) {

        case "js":
            return "javascript";

        case "ts":
            return "typescript";

        case "html":
            return "html";

        case "css":
            return "css";

        case "py":
            return "python";

        case "json":
            return "json";

        case "md":
            return "markdown";

        default:
            return "plaintext";
    }
}
Important: This function only identifies the language. It does not teach Monaco how the language works.

4. Assign the Language to the Editor Model

After identifying the file type, the language is associated with the editor model. 

monaco.editor.setModelLanguage(
    editor.getModel(),
    "javascript"
);

The language ID tells the editor which language support should be associated with the current source text.

app.js ↓ .js ↓ javascript ↓ Editor Model ↓ JavaScript Language Support

5. Language Definition

A language definition describes how the editor should recognize pieces of source code.

For example:

const name = "Srinivas";

function hello() {
    console.log(name);
}

The editor can conceptually identify:

const → keyword name → identifier "Srinivas" → string function → keyword hello → identifier console → identifier

6. Tokenization

Tokenization means breaking source code into meaningful tokens. 

const age = 25;

Conceptually:

constkeyword
ageidentifier
=operator
25number

Source Code ↓ Tokenizer ↓ Tokens ↓ Syntax Highlighting

7. Monarch Tokenizer

Monaco provides a tokenizer system called Monarch for defining syntax highlighting rules. Monarch language definitions can contain tokenizer states and rules.

A simplified example:

const javascriptLanguage = {

    keywords: [
        "const",
        "let",
        "var",
        "function",
        "return",
        "if",
        "else"
    ],

    tokenizer: {

        root: [

            [
                /[a-zA-Z_$][\w$]*/,
                {
                    cases: {
                        "@keywords": "keyword",
                        "@default": "identifier"
                    }
                }
            ],

            [
                /[0-9]+/,
                "number"
            ],

            [
                /".*?"/,
                "string"
            ],

            [
                /\/\/.*$/,
                "comment"
            ],

            [
                /[=+\-*\/]/,
                "operator"
            ]
        ]
    }
};

This is a simplified learning example, not a complete JavaScript grammar.

Monaco can register a Monarch tokenizer with:

monaco.languages.setMonarchTokensProvider(
    "myjavascript",
    javascriptLanguage
);

8. Language Configuration

Tokenization is not enough. The editor also needs to know comments, brackets, auto-closing pairs, indentation and other editor behavior. 

monaco.languages.setLanguageConfiguration(
    "myjavascript",
    {
        comments: {
            lineComment: "//",
            blockComment: ["/*", "*/"]
        },

        brackets: [
            ["{", "}"],
            ["[", "]"],
            ["(", ")"]
        ],

        autoClosingPairs: [
            { open: "{", close: "}" },
            { open: "(", close: ")" },
            { open: "[", close: "]" }
        ]
    }
);

9. Syntax Highlighting

After tokenization, the editor maps token types to visual styles.

Token ↓ Token Type ↓ Theme ↓ Visual Style / Color

This is why changing the editor theme changes the appearance without changing the source code.

10. Syntax Highlighting Is Not Full Language Understanding

Level 1 — Text

const x = 10;

The editor simply stores text.

Level 2 — Tokenization

const is a keyword, x is an identifier and 10 is a number.

Level 3 — Parsing

The code can be represented as a structured syntax tree.

VariableDeclaration
    |
    +-- Identifier: x
    |
    +-- Literal: 10

Level 4 — Semantic Analysis

The editor can understand relationships between symbols, such as which variable declaration a particular reference belongs to.

Level 5 — Language Services

Advanced editor features include autocomplete, diagnostics, hover information, go-to-definition, references, rename, formatting and code actions.

11. Language Services

JavaScript ↓ Parser / Language Service ├── Diagnostics ├── Completion ├── Hover ├── Definition ├── References └── Rename

Language services are responsible for the deeper understanding needed for intelligent editor features.

12. JavaScript and TypeScript in Monaco

function add(a, b) {
    return a + b;
}

const result = add(10, 20);

A richer language service can understand:

Function: add Parameters: a, b Variable: result Function Call: add()

JavaScript and TypeScript use Monaco's TypeScript language-service infrastructure for richer language features.

Possible features include:

  • Autocomplete
  • Diagnostics
  • Hover information
  • Go to definition
  • Find references
  • Rename symbol

13. Web Workers

Language analysis can be expensive. A language service can run in a Web Worker so that heavy analysis does not block the main editor UI.

Browser | +--------------------+ | | v v Editor UI Language Worker | | +---- Messages ------+

The editor sends model information to the worker, the worker performs analysis, and the results are returned to the editor.
